- 形式：8 个并行子系统审查子代理发现 → 我亲自核读关键文件 → 1 个对抗性交叉验证子代理裁定
- 日期：2026-08-01

## 审查方法

由 **8 个并行子代理** 按子系统分工排查（mac SSH 层 / mac UI / mac Store / mac Proxy+Highlight / win 核心 / win 桥接 / win UI / 死代码清理），产出约 120 条原始候选。随后：

1. 我亲自**逐行核读**了 11 个关键文件（NIOSSH / OpenSSH / Local 三套 SSH 传输、LSPClient、Keychain、SSHKeys、BackupBundle、AppDelegate+Sessions、WebSSHView、DownloadTasks、ProxyConfig/Handlers）。
2. 启动 **1 个对抗性验证子代理** 对 20 条核心候选逐一判 `CONFIRMED / PLAUSIBLE / REFUTED`。

### 关键去伪（被排除的误报）

这是本次审查最有价值的部分——原始候选大量是假阳性：

- **`AppDelegate+Sessions.swift` 的 9 条"后台线程改 UI"崩溃告警 → 全部 REFUTED**。核读确认 NIOSSH/OpenSSH/Local 三套 SSH 传输的 delegate 回调与 exec 完成**全部经 `DispatchQueue.main.async` 切回主线程**，信号不跨线程。
- **WebSSHView 域名绕过（`hasSuffix`）→ REFUTED**：`notexample.com` 不以 `.example.com` 结尾，匹配逻辑实际正确。
- **`deleteHost` 不刷新 UI → REFUTED**：实际调用了 `refreshHostUI()`。
- **win AgentCLI exec/type 命令注入 → REFUTED**：参数走 HTTP JSON 字典而非 shell 拼接，且已有 token 鉴权。
- **win icacls 注入 → REFUTED**：权限操作用 `RestrictToCurrentUser` 且参数非用户输入。
- **win ScpBackend UI 死锁 → REFUTED**：`Task.Run` 不依赖调用线程，只是卡顿非死锁。
- **mac LSP `send()` 存 `msg:[:]` → REFUTED**：刻意设计，握手类请求本就不该做 -32801 重试。

## 正式裁定（按严重度排序）

### 高危（真实漏洞 / 数据损坏）

### 1. Win SFTP 下载路径穿越
**实现文件**：`win/Bridge/BridgeRoutes.cs` : 260

`RouteSftpDownload` 的 local 路径没有任何路径穿越校验。攻击者 / 恶意 agent 提交 `local='../../ProgramData/x'` 经 SFTP 下载接口，可把文件写到系统任意位置，配合上传接口可覆盖敏感文件。

### 2. Win EscapeArg 命令注入（回落路径）
**实现文件**：`win/Sftp/RemoteFs/ScpBackend.cs` : 108

`EscapeArg` 只处理空格和双引号，未转义 `$ \` ; | &` 等 shell 元字符。当远端文件名含 `$(curl …|sh)` 且走 `ssh.exe → 远端 shell` 的 `ExecAsync` 路径时，文件名会被解释执行。仅 `CreateCommand`（不经 shell）路径安全——**触发条件取决于实际是否落到 shell 执行路径**。

### 3. Mac 快捷命令删除后被默认集覆盖（数据丢失）
**实现文件**：`mac/Sources/PixShell/Store/QuickCommands.swift` : 42

`load()` 在 JSON 为 `[]`（空数组）时回退到默认集并回写。用户**删除全部自定义命令**后，重启应用被默认命令覆盖。

### 4. Mac Keychain 读写竞争
**实现文件**：`mac/Sources/PixShell/Store/Keychain.swift` : 151

`setPassword` 的读-改-写（`loadMap → modify → saveMap`）**无锁**。并发调用 `setPassword`/`delete` 时后写覆盖先写，导致密码保存丢失。当前主调用路径接近单线程，触发概率较低。

### 5. Mac WebDAV 备份密码明文存储
**实现文件**：`mac/Sources/PixShell/Store/BackupBundle.swift` : 45

WebDAV 备份密码以**明文 JSON 存 UserDefaults**，与 Keychain 里加密凭据的做法不一致。同用户任意进程可读 `~/Library/…/plist` 得到 WebDAV 用户名 + 应用密码。

### 6. Proxy IPv6 CONNECT 缺方括号
**实现文件**：`mac/Sources/PixShell/Proxy/ProxyHandlers.swift` : 369

HTTP CONNECT 请求行未对 IPv6 目标加方括号，构造非法请求行。`destHost='::1'` → `'CONNECT ::1:443 HTTP/1.1'` 不含 `[ ]`，违反 RFC 7231，导致 IPv6 直连 / 代理失败。

### 7. Proxy ID 冲突
**实现文件**：`mac/Sources/PixShell/Proxy/ProxyConfig.swift` : 91

`newId()` 用**毫秒时间戳**做 ID。同一毫秒创建两个代理会得到相同 ID，`ProxyStore.upsert` 用 id 定位后会覆盖前者，前一条配置静默丢失。

### 8. Mac 下载任务数组竞争
**实现文件**：`mac/Sources/PixShell/Store/DownloadTasks.swift` : 21

`tasks` 数组在后台下载回调与主线程之间**无锁并发读写**。URLSession 完成回调在后台线程调 `finish()` 修改数组，同时主线程遍历，存在数据竞争 / 偶发崩溃风险。

### 9. Win LSP `_stdin` 空指针竞争
**实现文件**：`win/LSP/LSPClient.cs` : 186

`Write()` 中 `_stdin` 空检查与 `lock(_stdin)` **无原子保护**。`Shutdown` 置 null 可致竞态：`Send` 越过 null 检查后另一线程把 `_stdin` 置 null/关闭 → `lock(null)` 抛 `NullReferenceException` 或写已关闭流。

### 10. Mac LSP 重试无新超时保护
**实现文件**：`mac/Sources/PixShell/LSP/LSPClient.swift` : 224

-32801 重试换新 id 后**无新超时保护**，且 `Content-Length` 无上限。位置请求连遭 -32801 → 新 pending 无 10s 超时，若再失败则**永久挂起**；异常 `Content-Length` 可致无界内存分配。

### 中低危（体验 / 一致性问题）

### 11. SFTP 多选删除只删第一行
**实现文件**：`mac/Sources/PixShell/UI/SFTPPanel.swift` : 883

`del()` 仅删除第一选中行，与多选 UI 不一致。用户在远端文件表多选若干文件按 Delete，只删第一行，其余保留。

### 12. Win 主窗口关闭泄漏子窗口
**实现文件**：`win/MainWindow.xaml.cs` : 2770

`OnClosed` 不关 `_sysInfoWin/_connMgrWin` 子窗口。关主窗口时子窗口仍持有指向已释放 MainWindow 的回调，后续交互引发 `ObjectDisposedException`。

### 13. Win 读线程未 join
**实现文件**：`win/TerminalSession.cs` : 1744

`_readThread` 在 `Dispose` 后未 join，读线程可能访问已释放流 / WebView2，抛 `ObjectDisposedException` 逃逸到线程池。

### 14. Mac CPU 百分比解析丢数据（PLAUSIBLE）
**实现文件**：`mac/Sources/PixShell/Monitor/SysInfoParser.swift` : 92

CPU 百分比用 `Double(value)` 解析，带 `%` 后缀时返回 nil 丢数据。当前 `monitorCommand` 输出纯数字不受影响；若远端输出变 `'95.5%'` 格式则 CPU 占用全丢失。（机制真实，触发取决于远端输出格式。）

### 15. Mac AgentChat 重复启动进程（PLAUSIBLE）
**实现文件**：`mac/Sources/PixShell/UI/AgentChatView.swift` : 113

`running` 标记在异步回调中才置位。发送瞬间连点 → `running` 未及时置位 → 可启动多个 CLI 进程，停止按钮只能终止最新一个。（触发窗口极窄。）

## 值得注意但未进 Top-15 的次要点

- **win `MonitorSidebar.Update()` 无线程契约**：当前主调用路径（DispatcherTimer 回调）在 UI 线程，属"未来扩展地雷"，非现网 bug。
- **win 多处 `async void`**（WebdavPush/Pull、ToolsPanel.Run、SysInfoWindow 刷新）：Push/Pull 内已有 try/catch 不崩，但 `async void` 仍是脆皮模式，建议统一改 `async Task`。
- **若干性能项**（DispatcherTimer 未 Dispose、ToolsPanel 提前建窗、Reload 全量重建）——真实但影响极小。

## 优化建议分组

### A. 持久化与凭据安全（优先级最高）
1. **QuickCommands 判空边界**：`load()` 应区分"文件存在但为空"（返回空集）与"文件不存在"（返回默认集），不要对 `[]` 回退默认。
2. **Keychain 加锁或串行化**：把读-改-写包进一个串行队列 / 文件锁（`NSLock` 或 actor）。
3. **WebDAV 密码应收敛进 Keychain**：与 SSH 凭据同一 AES-GCM 存储，去掉明文 plist 分支。

### B. 代理与 IPv6
4. **CONNECT 目标规范化**：构造请求行前按目标是否含 `:` 判断补 `[ ]`（或全程用 `URL` 解析）。
5. **`newId()` 加单调递增计数器**（进程内 atomic），避免毫秒时间戳碰撞。

### C. 并发安全
6. **DownloadTasks 加锁 / 切主线程写**：所有 `tasks` 修改统一回主线程或用 `NSLock`。
7. **win LSP `_stdin`**：`lock` 一个永不置 null 的 `_stdinLock` 对象，`_stdin` 置 null/读写都在锁内判断。
8. **mac LSP 重试**：为每个新 pending 也挂一个超时（复用已有 10s 逻辑），并给 `Content-Length` 加合理上限。

### D. 桥接安全
9. **SFTP 下载/上传路径**：对 `local` 做规范化 + 前缀校验（拒绝 `..`、绝对路径逃逸、分隔符穿越）。

### E. 一致性 / 生命周期
10. **SFTPPanel 多选删除**：遍历所有选中行删除，或删除后刷新选中集。
11. **Win 子窗口**：`MainWindow.OnClosed` 中统一关掉 `_sysInfoWin/_connMgrWin`。
12. **Win 读线程**：`Dispose` 时 join（带超时）后再释放资源。
13. **`async void` → `async Task`**：全局收敛，防止异常逃逸到同步上下文。
